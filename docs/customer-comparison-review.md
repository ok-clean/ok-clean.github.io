# 고객 견적 비교 서버 로직 — 에뮬레이터 시제품

## 기능과 접근 범위

시험용 비교 처리기는 검증된 이메일·전화 계정의 UID로 요청 소유자를 확인하고, 고객 본인의 열려 있는 요청만 조회한다. 비교 응답에는 업체 상호와 금액만 포함한다. 고객 이름·전화, 업체 UID, 배정 ID, 견적 비고는 반환하지 않는다. 공개 UI, HTTP 서버, 실제 인증과 운영 DB는 연결되지 않았다.

`comparison-reader.cjs`는 Firestore Web SDK와 에뮬레이터의 가상 관리자 계정으로 시험한다. 트랜잭션에서 요청 소유권을 먼저 확인하고 슬롯·포인터·권한 문서·업체 승인 버전과 견적을 대조한다. 승인 취소나 재승인으로 이전 권한이 무효화된 경우 가격을 제외한다. 배정 데이터가 일치하지 않으면 실패로 처리한다. 비교 결과는 조회 시점에만 유효하며 이후 업체가 회수되거나 상태가 바뀌었을 때 이미 전달된 응답까지 지우지는 못한다.

`comparison-handler.cjs`는 토큰 검증·속도 제한·읽기 함수를 외부에서 주입받는 서버 전용 시험 코드다. 토큰 진위, 폐기, 속도 제한은 여기서 실제 구현하지 않았다. 브라우저에 관리자 데이터베이스 권한을 노출하거나 이 모듈을 번들링하면 안 된다. 관리자 SDK는 규칙을 우회하므로 운영용 서버는 인증·권한·소유권·정보 최소화를 독립적으로 강제해야 한다.

## 남은 출시 조건

- 기존 익명 신청 UID를 인증 계정에 안전하게 연결하거나 별도의 소유권 확인 방식을 구현하고, 분실·계정 변경을 다룬다. 서로 다른 UID를 같은 사람이라고 가정하지 않는다.
- 실제 Firebase 토큰 검증·폐기 확인, 안전한 서버 실행과 속도 제한, 재시도·타임아웃과 감사 기록을 구현한다. HTTPS 경로와 응답의 no-store도 필요하다.
- 화면은 모든 업체 상호를 문자 그대로 표시해야 하며 HTML로 해석하면 안 된다. 정확한 가격 조건·고객 동의·업체 정보 공개 정책, 견적 유효기간과 선택·예약 흐름이 필요하다.
- 현재 요청이 예약확정·완료·종료이거나 날짜가 지나면 비교가 제공되지 않는다. 예약 취소·재개 및 예외 처리 방식은 운영 정책 확정 전이다.
- 본 시제품은 세 업체 슬롯을 전제로 하며 #19 및 선행 PR에 의존한다. 이전 스키마 이관, 기존 회원 규칙과 통합, 운영비·보존/삭제·실기기 검증이 필요하다. 운영 Firebase 규칙을 덮어쓰지 않는다.
