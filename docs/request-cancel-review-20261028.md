# 고객 견적 요청 취소 — 에뮬레이터 전용 초안

PR #21을 기반으로 한 시험 코드다. 실제 서버·고객 화면·Firebase 운영 규칙·고객 데이터에는 연결하지 않는다. 영업 정책 확정과 별도 승인 전 배포하지 않는다.

## 시험 가정과 상태 전환

| 현재 상태 | 고객의 취소 처리 |
| --- | --- |
| 신규·검토중·상담중 | 본인 확인 후 취소로 변경 |
| 취소 | 같은 소유자의 반복 요청은 이미 취소된 것으로 처리 |
| 예약확정·작업완료·종료 | 이 기능으로 변경하지 않음. 실제 운영 시 별도 상담·취소 정책 필요 |

시험 규칙에서 취소 상태는 관리자도 다른 상태로 바꿀 수 없다. 재접수는 별도 요청으로 설계해야 하며 기존 배정 권한을 되살리지 않는다. 과거 날짜여도 상태가 아직 신규·검토중·상담중이면 이 시험에서는 취소할 수 있다. 이 규칙은 운영 정책을 확정한 것이 아니다.

## 시험 구현

- 고객은 Firestore의 요청 원본을 직접 읽거나 수정할 수 없다. 신뢰 서버 시험 로직이 먼저 검증된 동일 UID의 소유권을 확인하고 단일 트랜잭션으로 상태만 바꾼다. 다른 고객의 요청과 없는 요청은 동일한 응답을 보낸다.
- 취소는 개인정보 삭제가 아니다. 원본 요청과 과거 배정·견적은 남으며, 신규 접근과 신규 견적을 막는다. 실제 보관 기간·삭제·관리자 감사 이력은 별도 정책과 구현이 필요하다.
- 취소 후 업체는 서버 보안 규칙상 해당 요청의 배정·최소정보·견적을 새로 조회하거나 견적을 제출하지 못한다. 이미 읽거나 복사한 내용, 기기 캐시와 기존 통지까지 회수하지는 못한다. 업체에게 취소를 알려주는 기능도 구현하지 않았다.
- `request-cancel-handler.cjs`의 토큰 검증·요청 제한은 주입된 시험 함수다. 실제 Firebase 토큰 검증·폐기 확인, 분산 제한, HTTPS 서버와 로그 정책은 구현되지 않았다. 익명 신청 UID가 검증된 계정 UID와 같다는 조건만 시험하며 실제 계정 연결·분실 복구는 구현하지 않았다.
- `request-cancel-store.cjs`는 에뮬레이터의 가상 관리자 Web SDK 계정으로만 시험한다. 운영 서버의 Admin SDK는 Firestore 보안 규칙을 우회하므로 인증·소유권·상태 전이·최소 권한을 서버에서도 독립적으로 강제해야 한다.
- 예약 확정과 취소가 동시에 진행되면 Firestore 규칙의 거부가 일시 오류(503)로 돌아올 수 있다. 이 경우 취소 성공이라고 알리지 않고, 상태를 다시 확인할 방법과 불확실한 결과 안내가 필요하다. 현재는 자동 재시도나 고객 화면을 구현하지 않았다.

## 검증 범위

가짜 고객·업체로 본인·타인·익명·미인증, 없는 요청과 타인 요청의 동일 응답, 중복 취소, 취소 후 업체 읽기·견적 차단, 과거 기록 유지, 예약 이후 취소 거부, 관리자 직접 쓰기 우회, 취소와 배정·예약의 동시 처리를 검사한다. 에뮬레이터의 동시성 동작은 운영 Firestore의 모든 동작을 재현하지 않으므로 별도의 운영 환경 검증이 필요하다.

이 설계는 대기 중인 요청의 취소만 다룬다. 예약 취소·환불·결제·고객 알림·업체 알림·실제 사진 삭제는 포함하지 않는다.
