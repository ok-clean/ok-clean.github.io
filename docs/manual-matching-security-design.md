# 수동 매칭 MVP: 데이터 및 보안 설계 초안

상태: 설계만. 운영 계정·규칙·데이터를 수정하거나 프로젝트를 생성하지 않는다.

## 단계

1. 고객은 서비스, 지역, 면적, 희망 날짜를 입력하고 처리 방식을 확인한다. 직접 시공 또는 제휴업체 연결 가능성을 사전 안내한다.
2. 고객 동의 후 요청을 저장한다. 저장 성공 응답을 받기 전에는 접수 완료로 표시하지 않는다. 실패 시 재시도와 카카오톡 문의를 안내한다.
3. 관리자는 인증된 계정으로만 요청을 보고 직접 시공 또는 제휴업체를 수동 선택한다. 사진은 초기에는 고객이 직접 카카오톡으로 제공한다.
4. 업체·고객에게 필요한 정보만, 별도의 동의와 권한을 확인한 후 제공한다. 초기에는 사이트에서 업체별 데이터 공개 기능을 활성화하지 않는다.

## 후보

- GitHub Pages는 정적 화면을 제공한다. 고객 요청·사진·관리자 권한을 공개 저장소에 저장하지 않는다.
- 기존 Firebase 프로젝트에는 Firestore 회원 코드가 존재한다. 별도 테스트 프로젝트나 에뮬레이터에서 견적 요청 스키마와 규칙을 먼저 검증한다. 현재 운영 규칙·요금제는 확인되지 않았다.
- Firebase Cloud Storage는 2026-02-03부터 Blaze 결제 계정 연결이 필요하다. 무상 할당 범위가 있더라도 사용자 승인 없이 활성화·연결하지 않는다.
- Supabase Free는 파일 저장 무료 할당이 있으나 비활성 프로젝트 일시 중지 등의 운영 제한이 있다. 새 가입·프로젝트 생성은 하지 않았다.

## 요청서 최소 데이터

서비스 종류, 시·군, 면적, 희망 날짜, 연락 방법과 연락처, 접수 시각, 처리 상태, 필수 동의 버전 및 시각. 상세 주소는 초기 수집하지 않는다. 사진에는 주소·가족사진 등 민감한 내용이 있을 수 있어 안내가 필요하다. 서버의 관리용 메모·담당자·견적은 고객이 생성·수정할 수 없어야 한다.

## 권한 경계

- 비로그인 고객: 검증된 요청 생성만. 전체 목록 조회 금지. 익명 인증은 신원 확인이 아니다.
- 관리자: 별도 인증과 서버 측 권한 검증을 통과한 계정만 읽기·상태 변경. 프론트에서 버튼을 숨기는 것만으로 권한을 보장하지 않는다.
- 제휴업체: 기본적으로 접근 불가. 추후 승인된 업체에 명시적으로 배정된 요청의 최소 정보만 제공. 연락처와 주소는 별도 동의와 업무 단계에 따라 제공.
- 인증 정보와 관리자 비밀키는 공개 저장소·클라이언트에 넣지 않는다. 공개 가능한 클라이언트 설정값이 비밀키를 대체하지 않는다.

## 남은 보안·운영 조건

- 운영 규칙 확인 전에는 기존 Firestore 규칙을 교체하지 않는다. 신규 컬렉션에 대해 허용 필드·형식·길이, 서버 시간, 관리자 권한을 명시한다.
- 스팸은 익명 인증만으로 막을 수 없다. App Check, 서버 측 요청 제한·중복 방지, 모니터링과 수동 차단을 조합하고 오탐 시 복구 경로를 마련한다. App Check 시행 전 기존 회원 기능 영향부터 테스트한다.
- 사진 기능은 비공개 저장소, 파일 크기·형식 제한, MIME 및 파일 내용 검증, 악성 파일 검토, 메타데이터 제거 여부, 짧은 유효기간 접근과 삭제 정책을 설계·검증하기 전 연결하지 않는다.
- 개인정보 처리방침에 실제 수집 항목·보유 기간·위탁·제공 대상과 이용자 권리 행사 방법을 운영 실태에 맞게 명시한다. 자동 삭제를 구현하기 전 자동 삭제된다고 주장하지 않는다.
- 테스트는 가짜 데이터와 에뮬레이터를 사용한다. 익명 목록 읽기 거부, 다른 고객 데이터 거부, 관리자만 접근, 잘못된 필드 거부, 실패 시 재시도·중복 방지 및 로그의 개인정보 노출 여부를 확인한다.
