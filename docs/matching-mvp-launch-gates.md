# 춘천 수동 매칭 MVP 운영 전 보안 게이트 (검토용)

상태: 문서 초안. 운영 배포, Firebase 설정 변경, 실제 고객 데이터 수집 없음.

## 현황 및 선행조건

- PR #5의 화면은 운영 백엔드와 연결되지 않은 시제품. Firestore 규칙은 에뮬레이터 전용이며 운영 규칙으로 덮어쓰지 않는다.
- PR #8은 Pages 업로드에서 prototype 제외를 제안하지만 공개 저장소 소스의 공개를 막지 않는다.

- PR #3의 개인정보 안내는 운영 Firebase 규칙, 보존·삭제 실태와 대조 전 게시 확정하지 않는다.

## 고객 신청에서 예약까지의 최소 흐름
1. 춘천 지역, 서비스 종류, 면적, 희망일과 최소 연락처만 수집. 상세 주소·사진은 초기 요청서에서 제외.
2. 처리 목적, 직접 시공 또는 승인 제휴업체 연결 여부, 제3자 제공 동의를 구분. 저장 성공 전 접수 완료로 표시하지 않는다.
3. 인증된 관리자만 원본 요청 조회. 서버 측 권한 검사 및 접근 기록을 적용한다.
4. 업체는 실제 사업자 확인 후 관리자가 승인. 승인·배정된 업체에만 서비스/지역/면적/날짜 등 제한된 정보 제공. 이름·전화·상세주소는 기본 제공하지 않는다.
5. 배정 업체만 1회 견적 제출, 수정·취소는 관리자를 통해 기록. 고객 비교는 본인 확인된 채널에서만 제공.
6. 고객의 선택과 예약 확정, 작업 완료, 철회·삭제 요청을 상태와 감사 기록으로 관리.

## 필수 테스트 (운영 전)
- 비인증 요청 목록·상세 조회, 다른 고객 조회, 미승인·미배정 업체 조회·견적 제출 모두 거부.
- 관리자 권한은 클라이언트 값이 아닌 서버에서 검증. 관리자 지정·해제 절차 및 권한 변경 즉시 반영 확인.
- 필드 허용 목록, 서버 시간, 요청 횟수 제한, 재전송 idempotency 키, 중복 접수 탐지, 스팸 대응 및 오탐 복구 확인.
- 업체별 정보 격리, 배정 취소 시 접근 차단, 고객 연락처의 견적/로그/알림 누출 방지.
- 사진 업로드는 기본 비활성. 활성 전 서버 파일 내용·MIME·크기 검증, 비공개 보관, 접근 만료, 악성 콘텐츠 대응, 메타데이터 및 삭제 검증.
- 운영 Firestore 기존 회원 규칙과 신규 규칙 병합 테스트. 별도 에뮬레이터와 가짜 데이터 사용.
- 보존 기간, 삭제 요청 처리, 백업·로그 포함 삭제 정책과 개인정보 안내 일치 확인.

## 출시 판단
- 현재 단계: 비공개 설계 및 테스트만 허용. 실제 고객 신청·업체 접속·자동결제·유료 과금 활성화 금지.
- 별도 승인 전 main 병합·Pages 배포·실운영 Firebase 규칙 변경·유료 서비스 가입 금지.
- 승인 검토 시 실기기, 카카오/전화 경로, 기존 견적·회원·SEO 회귀 테스트와 개인정보 처리방침의 실제 운영 일치 여부를 확인한다.

## 접수 확인 API의 권한 경계 (추가 검토)
- PR #12의 `checkOwnQuote`는 현재 Firestore 관리자 권한 테스트에 한정된다. 고객 브라우저에 관리자 자격 증명 또는 Admin SDK를 제공하지 않는다.
- 고객이 로그인되지 않았거나 익명 UID가 변경된 경우 요청 ID만으로 본인임을 증명할 수 없다. 요청 ID나 전화번호만으로 조회 권한을 부여하지 않는다.
- 서버는 인증된 고객 식별자와 원본 요청의 소유자·확인된 연락 수단을 대조한다. 조회 결과는 최소한의 상태/접수 여부만 반환하고 이름·전화·업체 메모를 포함하지 않는다.
- 응답은 확인됨/미확인/일시적 오류를 구분하고, 오류·미확인에서 자동 재접수하지 않는다. 조회 요청 제한과 접근 감사 기록을 적용하되 로그에는 개인정보를 남기지 않는다.
- 실제 고객 조회 기능을 공개하기 전 Firebase 운영 인증·기존 회원 권한·개인정보 처리방침과 충돌 여부를 검증한다.

## 수동 매칭 업체 견적 단계 출시 전 검증
- 승인된 업체의 계정 인증과 실제 사업자 검증은 별개다. 관리자의 사업자 확인 및 승인·취소 이력을 보존한다.
- 배정은 관리자만 수행하고 승인된 업체에만 서비스·지역·면적·날짜를 공개한다. 업체에는 고객 이름·전화번호·상세 주소·원본 요청 문서를 제공하지 않는다.
- 업체 견적은 배정된 요청에만 생성 가능해야 하며 다른 업체의 견적과 고객 개인정보를 읽지 못한다. 배정 취소 또는 승인 철회 시 조회·제출 권한을 즉시 차단한다.
- 고객에게 견적 비교를 제공할 때에는 본인 확인된 채널을 사용한다. 업체 연락처 공유 및 예약 확정은 별도 동의와 기록을 검토한다.
- 시험용 Firestore 규칙에서 고객의 직접 조회는 금지되어 있으며, PR #12의 관리자 전용 조회 함수를 고객 화면에 연결하지 않는다.
