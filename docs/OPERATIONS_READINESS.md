# 무료 운영 후속 작업과 복구 경계

검토일: 2026-11-05 (한국시간). 이 문서는 회원가입 수정과 별도로 확인한 준비 상태이다.
이 문서 작성으로 운영 데이터 백업·삭제·예약 서버가 활성화되지는 않는다.

## 확인한 코드와 정책

- 작업 기준 main: `456665e0e75ae8d8c25455c2e62a7ea582bfcb31`. 회원가입 수정은 별도 변경분이다.
- 재사용 후보: 기존 준비 작업의 로컬 `c3fc8214809ca9da65f96c02adef076112e6cae3`에 있는 `server/retention.cjs`, `server/deletion-ledger.cjs`, `server/restore-gate.cjs`, `server/demo-restore-replay.cjs`.
- 위 서버 파일은 현재 공개 main에 적용된 예약 서버라는 뜻이 아니다. 준비 브랜치 전체를 가입 수정에 합치지 않는다.
- 운영자 확정 방향: 무응답 30일은 임시 종결, 상담 종료 후 90일은 상담자료 보존기간. 30일을 개인정보 삭제기간으로 해석하지 않는다.
- 현재 `privacy.html`은 회원정보에 탈퇴 요청 또는 마지막 이용 후 2년 기준을 안내한다. 상담 90일을 회원 전체에 적용하지 않는다. 실제 기산일 수집·자동 파기 구현 여부는 별도 확인 대상이다.
- 기존 회원 문서에는 상담 종료 시각·마지막 이용 시각·법적 보존 예외·첨부파일 목록이 없으므로 가입일이나 상태 문자열만으로 파기 대상을 확정할 수 없다.

## 준비 상태

| 항목 | 재사용 가능한 부분 | 실제 미완료 부분 |
|---|---|---|
| 예약 요청 | 준비 코드의 인증·중복·상태 전이 검증 | 공개 main의 무료 접수 화면/저장 규칙/관리자 목록 연결 |
| 상담자료 파기 | 종료 이력 기반 기간 계산, 미리보기, 버전 확인, 실패 재시도, 삭제 원장 | 운영용 종료 시각·예외 정책 연결, 관리자 실행 화면, 운영 실행 권한 |
| 첨부파일 파기 | 알 수 없는 종속 자료가 있으면 삭제 차단 | 실제 저장소·소유 관계 확인, 파일과 문서의 삭제 조정 |
| 백업·복구 | 삭제 원장 재적용, 복원 DB 확인, 만료/변조 증거 거부 | 실제 비공개 백업 보관 위치, 운영 자료 추출·암호화·전체 복원 검증 |

기존 `retention.cjs`의 실제 삭제 경로는 `demo-*` 프로젝트와 로컬 에뮬레이터만 허용한다. 운영에서는 읽기 전용 미리보기만 분리 지원한다. 이 보호 조건을 지우는 것으로 운영 구현을 대신하지 않는다. 시험 코드의 `reservationDays:30, historyDays:90`은 합성 시험값이며 운영자 상담 90일 정책의 구현 증거가 아니다.

## 무료 범위의 다음 구현

### 예약

가입 접수 정상화 후 서버가 필요한 자동 확정 구조와 분리하여, 인증된 고객의 예약 **요청**을 Firestore에 저장하고 관리자가 수동 확인하는 방식을 우선 검토한다. 별도 요청 식별값, 최소 고객 조회용 접수증, 요청 본문 검증, 관리자 전용 상태 변경이 필요하다. 같은 시간대 요청은 접수 가능하되 관리자 확인 전에는 확정으로 안내하지 않는다. 일정 충돌 방지를 구현하지 않은 상태에서 자동 예약 확정을 제공하지 않는다.

현재 준비 서버는 App Check, 복원 원장, 독립 검증·서명 자원을 전제로 한다. 무료 제약을 맞추기 위해 그 검증을 비활성화해 공개하지 않는다. 새 무료 요청 경로도 구현·규칙 검증·적용 승인 후에만 운영 연결 완료로 표시한다.

### 개인정보 처리

상담 기록에는 운영자가 확인한 종료 시각과 보존 예외를 기록하고, 종료 후 90일을 경과한 자료만 미리보기에 포함한다. 종료 여부/시각/예외가 불명확하면 삭제 대상에서 제외한다. 회원정보, 예약, 거래기록, 상담 이력, 첨부파일은 서로 다른 적용 대상으로 구분한다.

관리자 수동 실행은 대상 미리보기 → 승인 대상 확정 → 현재 버전 재확인 → 삭제 원장 기록 → 실제 파기 → 결과 재조회 순서로 구현한다. 대상이 변경되거나 연결 자료가 발견되면 중단하고 재검토한다. 처리 기록에는 이름·전화번호·메모 대신 결과 코드와 건수를 남긴다. 목록 숨김과 실제 파기를 구분한다.

### 백업

Firestore 관리형 내보내기/가져오기는 Blaze 및 결제 연결이 필요하므로 이번 무료 범위에서는 활성화하지 않는다. 공식 확인: <https://firebase.google.com/docs/firestore/manage-data/export-import> (2026-11-05).

무료 대안은 운영자가 인증한 관리 화면/로컬 도구에서 허용된 자료를 조회해 암호화된 백업을 생성하고, 운영자만 접근 가능한 보관 위치에 저장하는 방식이다. 아직 해당 기능과 위치가 연결되지 않았으므로 **백업 가동 중으로 표시하지 않는다**. 브라우저의 최근 500건 목록을 그대로 다운로드해 전체 백업이라고 표시해서도 안 된다. 전체 페이지 순회, 수량·스키마·생성 시각, 수집 중 변경 여부 및 불완전 상태를 포함해야 한다.

복구 범위는 회원 접수·최소 접수증·상담/예약 문서·관련 이력·삭제 원장이다. 인증 비밀번호/토큰/서비스계정 키는 백업에 넣지 않는다. Firebase Auth 계정과 UID 관계는 별도 복구 제약으로 기록한다. 파일 첨부는 실제 존재와 경로가 확인된 경우에만 포함한다.

백업에는 개인정보가 있으므로 공개 Git 저장소, Pages, 공개 CI 아티팩트에 저장하지 않는다. 암호화 비밀은 백업과 같은 공개 위치에 두지 않는다. 이 문서와 합성 검사 결과만 저장소에 보관한다.

## 복원 및 롤백 절차

1. 백업 원본을 보존하고 읽기 전용 사본으로 검사한다. 백업 생성 시각, 완전성, 스키마, 문서 수와 참조를 확인한다.
2. 운영 DB를 복원 대상으로 선택하지 않는다. 로컬 에뮬레이터의 분리된 합성 환경에서 먼저 복원한다.
3. 독립 보관한 최신 삭제 원장과 현재 보존기간을 적용해 삭제·만료 개인정보가 다시 나타나지 않게 한다. 최신 원장이 없거나 판정이 불명확하면 운영 공개를 차단한다.
4. 복원 전후 문서 수·필수값·UID 관계·접수증 연결·관리자 표시를 비교한다. 단순 JSON 파일 생성은 복원 검증이 아니다.
5. 실제 복구 전에는 백업 이후 새 접수와 관리자 변경을 분리 보존한다. 생성/수정 버전을 비교하고 기존 문서를 덮어쓰지 않는 병합 계획을 검토한다. 새 접수를 잃을 가능성이 남으면 진행하지 않는다.
6. 코드 롤백은 검증된 이전 사이트 버전 재배포로 한정한다. 데이터·삭제 원장·인증 계정을 코드와 함께 되돌리지 않는다. 저장 전 완료를 표시하던 취약한 가입 UI를 다시 열지 않고, 필요하면 접수 기능을 일시 중지한다.
7. 운영 규칙 복구는 기록한 직전 규칙으로 복귀하되 신규 접수 중단을 안내한다. 이미 저장된 합성/고객 자료는 별도 검토 없이 삭제하지 않는다.

## 이번 확인 근거와 한계

기존 준비 코드에서 아래 변경 없는 핵심 검사만 재사용 확인했다.

```sh
node --test tests/retention.test.cjs tests/deletion-ledger.test.cjs tests/restore-gate.test.cjs
```

43개 통과: 보존 대상 미리보기, 기간 경계, 상태·버전 변경 차단, 승인 없는 파기 차단, 실패 후 재시도, 원장 재적용 순서, 새 삭제 의도 발생 시 복원 공개 차단 등. **메모리 대역 기반 단위검사**이며 실제 Firestore 백업 생성·격리 DB 전체 복원·운영 파기 성공을 뜻하지 않는다. 실제 운영 데이터/권한/요금제 변경은 수행하지 않았다.

회원가입 수정본을 먼저 검토·적용하고, 본 문서의 후속 항목은 구현 완료·격리 검증·운영 검증을 각각 따로 보고한다.
