## 1. 정책 승인 문안 — 아직 미승인

운영자는 아래 문안을 승인하거나 변경할 수 있다. 승인되더라도 실제 삭제를 자동 실행하는 명령이 아니며 기존 회원정보에는 적용하지 않는다.

> 일반 상담은 고객이 종료 의사를 밝히거나, 견적·일정 협의가 끝나 추가 연락이 필요하지 않을 때 종료일을 기록한다. 필요한 마지막 회신 요청 후 30일 동안 응답이 없으면 임시 종결하되, 계약 이행·분쟁·약속된 회신이 남아 있으면 제외한다. 재문의는 별도 상담으로 관리하고 기존 자료의 보유기간을 자동 연장하지 않는다.
>
> 일반 상담정보는 적법한 처리 근거와 필요한 범위가 확인된 항목에 한해 상담 종료 후 90일 보유하고, 기간이 만료되면 사업자가 관리하는 자료를 안전하게 파기한다. 삭제 요청은 기간 만료 전에도 본인·대리권과 법적 보존 여부를 확인해 처리한다. 계약·결제·서비스 제공·분쟁 등의 법적 보존 대상은 필요한 자료만 구분하여 관리한다. 30일과 90일은 법정 의무기간이 아닌 운영정책이다.

**승인에 함께 필요한 범위**: 재견적·일정 재협의 목적의 추가 보유 필요성, 적법 근거, 실제 보유 항목, 종료일 기록 담당자, 매체별 삭제 방법·주기, 시행일. 단순히 '90일 승인'이라고 답하는 것만으로 미확정 보관 위치·외부 처리나 법적 근거가 확인된 것은 아니다.

재문의 빈도 등 실증 자료는 제공되지 않았다. 모든 사진·상세 주소·대화 원문을 일률적으로 90일 보유할 필요성이 입증된 상태는 아니다. 필요성이 없는 정보는 목적 달성 후 지체 없이 파기하는 원칙을 우선 검토한다. 동의를 근거로 보유하려면 적법한 수집·동의·철회 절차를 실제 적용 전 마련해야 한다. 정책 승인만으로 과거의 동의 부족을 소급 보완하지 않는다.

## 5. 최종 승인 단계와 보존 증거

1. 운영자에게 필요한 최소 묶음은 **정책 승인(항목·근거·기간·시행일 포함)**, **실제 보관/거래/외부 서비스 목록 확인**, **실기기 시험 및 파기·권리 대응 책임/대장 승인**의 3개다.
2. 이 답변/증거를 받으면 확인된 항목만 개인정보 생성 코드와 페이지에 반영한다. 필수 고지가 완성되면 A로 재판정하고 정확한 배포 대상 커밋·검사 결과를 붙여 별도 병합·배포 승인을 요청한다. 지금 운영 배포 승인을 요청하거나 승인된 것처럼 취급하지 않는다.
3. 현재는 B다. 실제 중대 문제가 확인된 경우에만 C로 구분한다. 기존 회원정보·실제 고객자료 삭제, Firebase 변경, 가입/예약 활성화, PR #56 수정, 유료 활성화, main 병합·배포를 실행하지 않는다.

제품 코드·처리방침은 8806800 그대로다. 16개 개인정보 검사, 320/390px, Actions `41007257509`·`41007257523` 성공과 7개 오프라인 결과를 재사용한다. 기존 검사/합성시험을 새로 요청하거나 재작성하지 않는다. 이 회차 변경은 이 docs 문서뿐이며 Pages 제외 경로다. 기존 stage 코드의 server/docs/tests 제외와 가입/예약 중지 코드는 바꾸지 않는다.

롤백: 34차 코드 `8806800`과 부모 `b4706da`, 기준 main `b924ed3`의 Git 객체·검증된 34차 Git bundle을 보존한다. 실제 배포 SHA로 오인하지 않는다. 최종 PR의 head/main 충돌·자동 Actions 상태는 PR 본문에 별도 기록한다. 이전 성공을 새 head 성공이라고 표시하지 않는다.
