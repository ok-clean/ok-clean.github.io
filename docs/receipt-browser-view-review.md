# 접수 조회 화면과 브라우저 검증 — 운영 미연결

PR #15의 읽기 전용 클라이언트를 화면에 연결하기 위한 별도 시제품입니다. main·운영 화면·Firebase 설정·개인정보·결제 기능은 변경하지 않습니다.

## 추가 파일과 경계
- `prototype/receipt-status.html`, `receipt-status.css`: 320px 이상 화면을 위한 조회 전용 화면. 실제 고객정보 입력·접수·예약 기능 없음. 시험 화면 고지, 입력 라벨, 결과 안내, 키보드 초점, JS 비활성 시 전송 차단.
- `prototype/security/receipt-view.js`: 신뢰할 수 있는 조회 함수만 주입하는 DOM 바인딩. 자동 조회·저장·토큰 입력·새 접수 기능 없음. 중복 호출, 무한 대기, 초기화 후 늦은 응답, 페이지 복원 시 결과 잔존 방지.
- `prototype/receipt-demo.js`: 네트워크를 사용하지 않는 고정 가상 응답. URL·저장소에서 엔드포인트/인증값을 읽지 않음. 다른 서버로 연결하는 옵션 없음.
- `tests/receipt-browser.cjs`: 실제 Chromium 320/390/1440px 브라우저 검증. HTTP 연동 검사는 루프백 HTTPS 서버와 가짜 인증·DB만 사용. 인증서와 키는 테스트가 임시 생성하고 삭제하며 저장소에는 포함하지 않음.
- 기존 PR 브라우저 워크플로에 추가 검사를 연결함. 운영 배포 워크플로 변경 없음.

## 재현 후 수정
조회 버튼 이벤트 직후 초기화하면, 아직 실행 전인 비동기 조회가 뒤늦게 시작할 수 있었습니다. 화면 초기화 세대 번호를 조회 실행 직전 다시 검사하도록 보완했습니다. 로컬 오프라인 Chromium DOM에서 재현 및 수정 후 통과를 확인했습니다.

## 검증 범위
- 입력값 검증, 중복 클릭, 성공/미확인/오류/무응답, 키보드·결과 초점, 가로 넘침, 초기화·새로고침·페이지 복원, 개인정보/인증값 비저장.
- 브라우저 → 기존 receipt-client → HTTPS 어댑터 → 소유권 핸들러 → 가상 DB → 결과 표시.
- 본인/타인/익명/미인증/잘못된 토큰, 요청 한도, 미존재, 오프라인에서 자동 재접수 없음.
- 로컬 컨테이너의 브라우저 URL 접근 정책상 루프백 전체 브라우저 테스트는 실행되지 않았습니다. 로컬 DOM 재현과 GitHub Actions 전체 검증을 구분합니다. 최종 CI 결과는 PR에 기록합니다.

## 운영 전 남은 조건
- 실제 Firebase 인증, 계정 연결 시 UID 유지, 토큰 폐기 확인, 실제 DB·분산 요청 제한·삭제 정책과 API 배포는 미구현/미연결입니다.
- 실제 인증 계정 변경·로그아웃 시 호스트 애플리케이션은 view.reset() 또는 destroy()를 호출해야 합니다. 시제품에는 인증 UI가 없습니다.
- 화면 초기화는 이전 결과 표시를 무효화합니다. 이미 시작된 서버 작업을 강제로 취소한다는 보장은 없으며, 기존 클라이언트·서버의 대기시간 제한이 별도로 적용됩니다.
- CSP connect-src 'self'는 동일 출처만 허용합니다. 운영 백엔드가 다른 출처라면 검증된 정확한 출처를 별도 승인 후 지정해야 하며 광범위 허용은 금지합니다.
- 자동화된 모바일 화면 크기 검사는 실제 휴대전화·스크린리더 검증을 대체하지 않습니다.
- PR #8의 Pages 시제품 제외를 선행 검토하고 #5→#12→#13→#14→#15 의존성을 고려해야 합니다. 승인 전 main 병합과 운영 배포 금지.
