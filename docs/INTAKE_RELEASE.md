# 회원 접수 정상화 승인 후보 — 2026-11-05

운영 접수 미검증, 이벤트 홍보 보류. 이 문서는 운영 적용 승인이 아니다.

## 확인된 원인
- main 가입 화면이 서버 저장 결과 전에 로컬 MEMBER와 완료 화면을 설정했다.
- 운영 Firebase okclean-admin / (default)는 2026-11-05 14:01 KST 관리자 전용 규칙이며 create/delete=false.
- 15시대 콘솔 재확인: Spark $0, Google·이메일만 활성화, 익명 미활성.
- 소스 규칙에는 관리자 UID placeholder가 남아 있어 실제 콘솔과 달랐다.

## 변경
- authStateReady 최대10초 대기, 기존 로그인 보존, 동시 익명 로그인 단일화.
- member_requests/{UID}와 member_receipts/{UID} 원자적 생성. 확인서는 UID·접수번호·코드·시각만 포함.
- 확인서 본인 get만 허용, list/수정/삭제 금지. 개인정보·관리 메모는 관리자만 조회.
- 중복 요청은 확인서 조회로 복구하며 기존 회원·관리자 처리내용을 덮어쓰지 않음.
- 익명 UID 기준 한 접수. 다른 브라우저/저장소 초기화 후 동일인의 중복 가입 판정은 보장하지 않음. 전화번호 본인인증 없음.
- 서버 확인 후만 완료 표시.15초 대기는 접수확인중이며 실패로 단정하지 않음.
- 관리자 캐시/미확정 목록 숨김, 로그아웃시 DOM내용 삭제, 서버접수0건과 오류 구분.
- 개인정보 안내의 실제 저장처를 Firestore로 정정. 회원 보존2년의 기존 안내는 이번에 연장하지 않음.

## 적용 승인 범위와 순서
1. 이 PR의 검증된 HEAD만 main 병합·Pages 공개 배포. 최신설치 PR70/72는 별도작업으로 덮어쓰지 않음.
2. 공개 app.js/member-sync.js가 후보와 일치하는지 확인. 구버전은 승인된 경로와 호환되지 않으므로 새 규칙에서 차단됨.
3. firestore.rules를 okclean-admin/(default)에 적용. 기존 Google 관리자 UID 유지, 일반 사용자의 신규접수/본인확인서만 추가.
4. Firebase Authentication 익명 제공업체 활성화. 유료 전환·SMS·Functions·Cloud Run 활성화 없음.
5. 운영 고객화면에서 합성접수→관리자조회/허용값수정→새로고침 검증. 쿠폰실사용/알림/카톡전송 실행하지 않음.
6. 기록한 테스트UID의 member_requests와 member_receipts만 콘솔에서 정리하고 테스트용익명계정만 정리. 운영 고객자료 변경금지. 삭제 직전 대상 대조.

## 복구
- 규칙은 기존14:01 관리자전용규칙으로 복원하면 신규접수 차단, 관리자조회/수정유지.
- 새 접수자료/확인서는 보존. 코드 되돌림과 DB복원을 혼동하지 않는다.
- 구버전 app.js의 거짓완료 동작으로 단순롤백하지 말고 신규접수중지판을 사용한다.
- 익명로그인 설정 복원시 이미 접수한 데이터는 삭제하지 않는다.
