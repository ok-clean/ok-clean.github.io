# 개인정보 보유·삭제 시험 범위

이 기능은 개발 중이며 **demo 프로젝트의 localhost Firestore 에뮬레이터에서만 실행**된다. 서비스에 배포되어 있지 않고 운영 데이터에 연결하거나 운영 데이터를 삭제할 수 없다. 실제 보유 기간, 법정 보존 예외, 백업과 삭제 권한 및 절차가 확정되기 전에는 운영 사용을 허용하지 않는다.

## 검증 대상과 처리

- 관리자가 작업완료·종료·취소로 기록한 최신 이력이 있고 정책상 정한 예약 보유일이 경과한 문서만 후보로 판단한다. 진행 중, 이력 누락, 다른 하위 컬렉션이 있거나 이력 200건 초과인 문서는 보류한다. 기존의 업체 관련 데이터도 자동 처리하지 않는다.
- 법적 보존 여부가 `legalHold:false`로 명시되지 않은 문서는 판정과 파기를 모두 보류한다. 해당 값은 검토·승인된 관리자 절차로만 설정해야 하며, 기존 데이터에 대해 자동으로 false를 채우지 않는다.
- ID만 읽는 제한된 페이지 스캔으로 후보를 수집한다. ID는 다른 정보와 결합할 수 있으므로 로그·공개 출력에 남기지 않는다.
- 기본 호출은 모의 점검이다. 시험 데이터 적용은 별도 `authorize` 검증 및 `apply:true`가 모두 필요하며, 이름·전화번호·요청사항·소유자·지문 등의 부모 문서 필드를 전체 교체하여 지운다. 영수증 번호 중복을 막기 위한 소유자 없는 최소 tombstone과 관리 이력만 별도로 남긴다. tombstone의 보유·식별 가능성은 개인정보 정책 검토 대상이다.
- 관리 이력은 정책의 별도 기간이 지나면 실제 하위 이력 문서를 삭제한다. Firestore TTL로 상위 문서만 지워서는 하위 컬렉션이 삭제되지 않는다. 이력 내부에 별도 하위 컬렉션이 발견되면 처리하지 않는다.
- 변경 또는 삭제 작업은 Firestore 트랜잭션에서 최신 상태와 이력을 다시 읽고 실행하며 성공 횟수·처리 결과를 개인정보 없는 감사 항목에 기록한다. 실패 시 `retry_needed`를 반환하고 별도 재실행한다. 실패 기록을 DB에 남기는 일 자체는 DB 장애에서 보장되지 않으므로 별도의 안전한 운영 모니터링이 필요하다.

## 운영 전 필수 결정 및 차단 사항

1. 예약 정보·관리 이력·tombstone 및 감사 로그 각각의 보유기간, 기준 시각, 법적 예외, 담당자와 수동 삭제·법적 보존 처리 방법을 정한다. 법적 보류 여부의 부재는 삭제 허가가 아니라 수동 확인 대상으로 취급한다.
2. 고객 요청 삭제, 고객 계정 삭제, 저장 사진 및 업체 매칭·제안·동시 업데이트 중인 데이터의 참조를 포함해 전체 데이터 목록을 확정한다. 현재 동시 타 서비스의 새 하위 컬렉션 생성은 트랜잭션 밖의 목록 검사만으로 막을 수 없으므로 운영 적용이 금지되어 있다. 삭제된 tombstone을 관리자가 수정·되살리지 못하도록 관리자 API와 규칙을 검증해야 한다.
3. Firestore TTL, 스케줄러 또는 작업자를 자동 활성화하지 않았다. 운영 데이터에 적용할 별도 인증·권한·단일 실행·경쟁 제어, 실패 재시도·감사·복구 및 사용자의 명시 승인이 필요하다.
4. 백업은 별도 보유·삭제 정책과 법정 의무를 확인한다. 현재 백업 열람·삭제·만료 변경은 수행하지 않으며, 백업에서 복원하면 이전에 삭제한 정보가 재생될 수 있으므로 대외 접근 전에 삭제 대상 재적용을 검증해야 한다. TTL·백업·삭제 작업은 사용량과 저장량에 따라 비용이 발생할 수 있다.
5. 운영의 실제 보유기간 설정, 개인정보 처리방침, App Check·Firebase 권한 및 운영 프로젝트와 격리된 시험 검증을 마치기 전에는 사용하지 않는다.
